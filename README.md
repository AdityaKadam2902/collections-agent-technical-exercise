# Collections agent

## Run it

```
python3 main.py --data-dir data --config config/policy.toml --out-dir outputs
```

Requires Python 3.11+ and nothing else — no `pip install` needed (see
`requirements.txt` for why). Writes `outputs/replay_log.csv`,
`outputs/replay_log.jsonl`, and `outputs/risk_flags.csv`.

Run the tests with:

```
python3 -m unittest discover -s tests -v
```

## What it does

Simulates the collections agent across the full 18 months of invoice,
payment, and reply history in `data/`, one calendar day at a time, seeing
only what would have been known as of each simulated day. Every reminder,
escalation, and reply-triggered decision it would have made is written to
the replay log rather than sent anywhere — this is a dry run. It also
produces a risk assessment for the 44 invoices still open at the end of the
history.

## Layout

```
main.py                 single entry point
config/policy.toml       escalation policy -- edit this, not the code
config/hold_overrides.csv  human record of resolved holds (empty by default)
data/                     the collections pack (unmodified)
src/
  data_loader.py          parses customers/contacts/invoices/payments/replies
  policy.py               loads policy.toml, answers "what tier applies now"
  classifier.py            rule-based inbound reply classification
  reconciliation.py       verifies payment claims against payments.csv
  render.py                 email body templates per tier
  engine.py                 the day-by-day replay simulation
  risk.py                    risk flagging for open invoices
tests/
  test_agent.py             unit tests: classifier, policy, reconciliation
  test_engine_integration.py   integration tests against the replay loop itself
outputs/                    generated by main.py: replay_log.*, risk_flags.csv, run_manifest.json
NOTES.md                    one-page policy rationale, known gaps, and AI disclosure
```

See `NOTES.md` for the reasoning behind the policy, what the agent may and
may not do without a human, and what would need to be true before any of
this sent a real email. See `GAPS.md` for a more detailed account of gaps
found while building this and what was done about each (kept separate from
NOTES.md so that file stays within the brief's one-page limit).
